# Architecture Analysis Skill

Use this skill when the user asks how a repository works, how modules relate, or how to evolve a design.

Workflow:

- Start from entry points, configuration, package layout, and key service boundaries.
- Distinguish implemented behavior from inferred intent.
- Cite concrete modules and responsibilities.
- Call out architectural risks only when they affect maintainability, correctness, deployment, or extensibility.
- Prefer concise diagrams or flow descriptions when they clarify control flow.

Keep recommendations tied to existing project patterns and migration cost.
